# 여행 탭 UI/UX 검사 — 목표: 트리플 근접

`/trips` 탭을 트리플(인터파크트리플) 여행 일정 화면 수준의 완성도로 끌어올린다.
**$1** 영역에 집중한다(비어 있으면 전체).

---

## 0. 먼저 할 것 — 코드만 읽지 말고 실제로 볼 것

```bash
npm run dev          # 또는 npm run build && npm run iphone:tunnel
```

Chrome DevTools를 **iPhone 뷰포트**로 두고 다음을 직접 렌더해 스크린샷을 남긴다.
읽기만 하고 판단하지 말 것 — 간격·정렬·정보 밀도 문제는 코드에 안 보인다.

1. `/trips` — 여행 0개(빈 상태) / 2~3개(목록)
2. `/trips/:id` — Day 1에 스톱 0개 / 1개 / 3개 이상
3. 같은 화면 **다크 모드**
4. 브라우저 글자 크기 200%(Dynamic Type 근사)

시드가 필요하면 `e2e/harness/seed.ts`의 `seedAuthedMap` 시드 데이터를 참고해 붙인다.

## 2. 현재 구조 — 바꾸면 안 되는 계약

여행 상세의 **Day N 스톱 = 그 날짜에 든 `events` 중 `place_id`가 있는 것**이다.
계획을 저장하는 별도 테이블이 없다(`lib/trips/tripDays.ts`가 기간에서 Day를 도출).

이건 설계 결정이다(CLAUDE.md §7 "상태는 도출, 저장 아님"). 캘린더 탭과 여행 탭이
같은 `events`를 다른 렌즈로 보기 때문에 불일치가 생길 수 없다.

**절대 하지 말 것:**
- `events.trip_id` 컬럼 추가 / `trip_stops` 같은 조인 테이블 신설 → 캘린더와 이중 관리
- 마이그레이션 추가(이 작업은 UI/UX 개선이다. 스키마 변경이 필요하다고 판단되면 **먼저 멈추고 보고**)
- API 키를 클라이언트에 노출(`VITE_`에 비공개 키 금지 — `npm run check:secrets`가 잡는다)
- `NaverMap` 공용 컴포넌트의 기존 props 시맨틱 변경(리캡 화면이 같이 깨진다)

## 3. 트리플 대비 구체적 갭 — 우선순위 순

트리플 일정 화면의 특징과 현재 상태를 대조한 것이다. 위에서부터 "트리플 느낌"에 기여도가 크다.

### ① 번호 배지 ↔ 지도 마커 번호 매칭 — **트리플의 시그니처, 지금 없음**
트리플은 스톱 리스트의 `1 2 3`과 지도 마커의 `1 2 3`이 눈으로 이어진다.
지금은 리스트에 번호가 아예 없고 마커도 기본 별표라 "순서가 있는 하루"로 안 읽힌다.
- 리스트 각 스톱 앞에 순번 배지
- 지도 마커에 같은 번호(`NaverMap`에 번호 마커 옵션 추가 — 기존 호출부 영향 없게 optional)

### ② 지도 ↔ 리스트 연동 — 지금 없음
스톱을 탭하면 지도가 그 마커로 이동·강조되고, 마커를 탭하면 리스트가 그 항목으로 스크롤.
`NaverMap`은 이미 `selectedId`/`onSelect`를 받는다 — 여행 상세에서 안 쓰고 있을 뿐이다.

### ③ 스톱 카드 정보 밀도 — 지금 너무 빈약
현재: 시간 + 이름 + 삭제 버튼.
트리플: 이름 + **카테고리** + 지역 + 체류 시간.
- `places.category`와 `places.region_label`이 이미 있다(`usePlaces`) — 쓰면 된다
- **사진 썸네일은 하지 말 것**: 사진 기능(P3c)이 미구현이라 데이터가 없다.
  회색 플레이스홀더로 채우는 건 빈 화면보다 나쁘다

### ④ 이동 수단·소요 시간 — 지금 거리만
현재 칩: `↳ 1.2km · 길찾기`.
트리플: 이동수단 아이콘 + 소요시간 + 거리.
- `directions` 프록시는 **자동차 기준 거리만** 반환한다(소요시간·수단 없음)
- 없는 값을 추정해서 표시하지 말 것. 프록시 응답에 없으면 표시하지 않는다
- 표시 가능한 개선: 칩을 스톱 사이 수직선과 시각적으로 잇기(지금은 떠 있음)

### ⑤ 레이아웃 — 지도가 작고 Day 바가 눌린다
트리플은 지도가 상단에 크게 붙고 리스트가 그 아래에서 스크롤된다.
현재 미니 지도는 200px 고정이라 동선이 잘 안 보인다.
- 지도 높이 재검토(스톱 수에 따라? 탭하면 확대?)
- Day 바를 스크롤 시 상단 고정(sticky) 검토

### ⑥ 순서 변경 — 지금 불가
트리플은 드래그로 순서를 바꾼다. 여기선 순서 = 이벤트 **시각**이라
드래그 = 시각 재배치가 된다. **비용이 크고 충돌 처리가 얽히니 마지막에**,
그리고 착수 전에 접근을 먼저 보고할 것.

## 4. 접근성 — 회귀 금지 (`.claude/rules/ux-and-accessibility.md`)

개선하면서 이걸 깨면 실패다:
- **색만으로 구분 금지** — 상태 칩은 색 + 텍스트(`여행 중`/`D-3`/`3일 전`). 번호 배지도 색만 의존 금지
- **터치 타깃 ≥44px** — 거리 칩·Day 버튼·삭제 버튼 전부. e2e가 칩 높이를 실제로 잰다
- **다크 모드** — 새 색은 CSS 변수로, 라이트/다크 양쪽 정의. 대비 WCAG AA
- **Dynamic Type** — 고정 px 폰트 금지, 글자 커질 때 줄바꿈 허용(고정 높이 박스 금지)
- **Reduce Motion** — 새 애니메이션은 `prefers-reduced-motion`에서 생략
- **빈 상태·로딩** — 모든 리스트에 필수. 지금 있는 것 제거하지 말 것
- 아이콘 전용 컨트롤은 `aria-label`

## 5. 제출 전 게이트 — 전부 통과해야 완료

```bash
npm run typecheck    # 0 에러
npm run lint         # 0 에러
npm test             # 전부 통과 (여행 관련: tripDays, dayLegs, tripDetailPage)
npm run build
npm run e2e          # e2e/trips-harness.spec.ts 포함
```

- 기존 테스트를 **고쳐서** 통과시키지 말 것. 의도적으로 동작을 바꿨다면 테스트도 바꾸되 **왜인지 설명**한다
- UI를 바꿨으면 `e2e/trips-harness.spec.ts`에 케이스를 **추가**한다
- 스냅샷 베이스라인은 darwin 것만 있다. 맥에서 작업하니 `SEED_SNAPSHOT=1 npm run e2e`로 갱신 가능 —
  단 **의도한 변경일 때만**. 무심코 덮어쓰지 말 것

## 6. 작업 방식

1. **먼저 진단만** — 위 ①~⑥을 실제 화면으로 확인하고, 스크린샷과 함께 무엇이 문제인지 보고한다.
   이때 고치지 않는다.
2. 무엇부터 고칠지 **합의한 뒤** 착수한다. ①②③은 비교적 싸고 효과가 크다. ⑤⑥은 크다.
3. 한 번에 하나씩, 각 단계마다 게이트를 돌린다.
4. 트리플과 **다르게 가야 하는 지점**이 보이면 그대로 말한다. 이 앱은 2인 공유이고
   트리플은 1인 계획 + 커머스다 — 모든 걸 똑같이 만드는 게 목표가 아니라
   "순서 있는 하루가 한눈에 읽히는" 느낌을 따라가는 것이 목표다.
